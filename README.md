# Pi Nest

本地、项目优先的 Pi Web 工作台。Pi 原生 Session 是唯一对话事实源。

## 日常运行

在本目录执行 `pnpm dev`（或 `pnpm start`），打开 **http://localhost:31415**。

这两个命令都先构建，再启动无文件监听的 Server；Web 构建产物会复制到私有发布目录。对话期间修改源码、stash/pop、提交、推送或重新构建不会替换当前页面。要使用新代码，等待任务结束后停止进程，再重新启动。`pnpm start:local` 是同一入口的兼容别名。

已有旧开发服务占用 31415 时，先等待其任务结束，再在原终端停止服务。不要同时启动两个运行服务。5173 的旧开发页面需要关闭，改用 31415。

## 项目首页

根地址显示项目首页，不会自动进入历史会话。可通过“打开项目”输入已有文件夹的绝对路径，或通过“新建项目”输入父目录和名称创建文件夹。路径指运行 Pi Nest 服务的电脑上的目录；不会覆盖同名文件夹。

添加后进入新对话草稿页，发送第一条消息时才创建 Pi 原生会话。已添加项目保存在 `~/.pi-nest/projects.json`，与 Pi 历史会话中的项目合并展示。侧栏“项目首页”可返回入口；带 `?session=...` 的旧会话链接仍然可用。移除项目仅隐藏入口，不删除目录或会话。

## 显式热更新开发

只在需要开发界面、允许页面热更新或重新加载时使用 `pnpm dev:hmr`，页面地址为 http://localhost:5173。

不要让这个页面中的 Agent 一边执行任务、一边回退或替换正在加载的应用源码。WebSocket 和运行协调器实现变化需要完整重新加载，不能混用新旧实现。日常对话使用上面的稳定入口。

## 检查

- `pnpm test`：包括临时仓库内的 stash/pop、拆分提交、构建资源改写与本地 bare remote 推送验证。
- `pnpm typecheck`
- `pnpm lint`
- `pnpm build`

项目架构、需求及排查记录见外层 `项目文档/INDEX.md`。
